# F0 — Prueba de concepto (v0)

Objetivo: un altavoz virtual propio que pase audio, instalado y probado en
esta maquina, **sin cambios en la app**.

## Requisitos (todo gratis)

- Visual Studio 2022 Community + workload "Desktop development with C++".
- Windows Driver Kit (WDK) + Windows SDK (misma version).
- Componentes VS extra: **Windows Driver Kit** (VSIX) + **librerias Spectre**
  (x64/x86). Sin ellos el build falla (MSB8020 / MSB8040).
- Windows en **modo test signing** (`bcdedit /set testsigning on`) con
  Secure Boot desactivado. Marca "Test Mode" en el escritorio; se revierte.

## Pasos

1. **Compilar**: `powershell -ExecutionPolicy Bypass -File tools\build.ps1`
2. **Instalar en modo prueba**: `tools\install-test.bat` (doble clic, UAC) —
   activa testsigning, importa el certificado del build e instala el driver
   con `devcon`. Requiere Secure Boot desactivado en la BIOS.
3. **Reiniciar** para que el modo de pruebas y el driver se activen.
4. **Verificar**: el dispositivo aparece en Configuracion de sonido y su
   `[Loopback]` es visible para WASAPI (pyaudiowpatch).
5. **Probar E2E**: apuntar la app al loopback del dispositivo y medir
   (huecos, latencia, CPU) frente a VB-Cable.

## Notas del entorno (esta maquina)

- Build con `tools\build.ps1` (MSBuild de VS2022;
  `SkipPackageVerification=true` porque el DPVerifier/InfVerif no carga en
  este entorno — es solo un chequeo de calidad del INF, no afecta al binario).
- Salidas: `driver\sysvad\TabletAudioSample\x64\Debug\TabletAudioSample.sys`
  y el paquete completo en `driver\sysvad\Package\x64\Debug\package\`
  (`sysvad.cat` firmado con `WDKTestCert`).
- `devcon.exe`:
  `C:\Program Files (x86)\Windows Kits\10\Tools\10.0.26100.0\x64\devcon.exe`.
- HWID del sample: `Root\sysvad_ComponentizedAudioSample`.
- WIL (dependencia de los APO) vendorizada en `wil/` (MIT).
